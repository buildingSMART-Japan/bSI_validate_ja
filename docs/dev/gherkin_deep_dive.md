# ガーキンルールの実装を深く掘り下げる
## 装飾家
### `@gherkin_ifc`
これは、`behave`デフォルトの `@step_implementation`デコレーターの代わりに使用され、コンテキストのスタッキングや、IFCモデル内のインスタンスの追跡と評価に関連するその他の機能を提供します。



### `@register_enum_type`
これは、列挙型をよりシンプルな方法で登録するための、小さな新しいデコレーターである。

## ステップハンドリング
### `execute_step()`
現在処理中のステップが`Given`か`Then` かをチェックする。

### `handle_given()`
`Given`ステップを処理する。

### `handle_then()`
`Then`ステップを処理する。

## コンテキスト・スタッキング
ステップが処理されると、それらは`behave.runner.Context`.型の永続オブジェクトに取り込まれる。このコンテキスト・オブジェクトには、`_stack`隠し属性があり、処理される各ステップの情報と結果を'スタック'するために使用される。



`context._stack`リストの各アイテムの`instances`属性の内容を監視することが役に立つ。

## 特集タグ
Behaveのフィーチャタグは、検証サービスにおいてGherkinベースのテストルールを分類し、実行を制御するために使用されます。これらのタグは、`.feature`ファイルの先頭に配置され、`--tags`オプションを使ってコマンドラインインタフェースから参照できます。また、ステップ実装ファイル内の`context.tags`アクセスできます。

### `@informal_propositions`そして`@implementer-agreement`
これらのタグは**規範的なIFCルールを**マークし、検証サービスにおいて**合格**、**不合格**、または**適用不可の**結果をもたらす。

> **注：** これらのタグは1つのタグに統合される予定です： `@normative-rule`。

これらのルールだけをコマンドラインで実行するには

> python3 -m behave --no-capture -v --tags=@informal-propositions --define input=/path/to/your.ifc

### `@industry-practice`
このタグは**ベストプラクティスのルールを**示す。これらの結果は、**合格**、**警告**、または**該当なしと**なります。

これらをローカルで実行する：
> python3 -m behave --no-capture -v --tags=@industry-practice --define input=/path/to/your.ifc

### `@disabled`
このタグでマークされたルールは**無効で**あり、検証サービスによって実行されることはない。

ルールを明示的に**除外**するには、同じ --tags 変数とハイフンを使用する：
> python3 -m behave --no-capture -v --tags=@informal-propositions --tags=-@disabled --define input=/path/to/your.ifc



### `@AAA000`
このタグは、**一部の機能**`AAA`と**ルール番号**（`000`）を識別する。例えば

- ジオリファレンス機能部分の4番目のルール（`@GRF000` ）は、`@GRF003` としてタグ付けされる。


### `@versionX`
このタグは、`.feature`ファイルのバージョンを示します。  
バージョン番号は、リリース後にルールに意味のある変更が加えられるたびにインクリメントされる。  
意味のある'変更とは、同じIFCモデルでも異なる結果をもたらす可能性のある変更である。

誤字脱字の修正や、ステップの実装に制御文字を追加するといった些細な変更は、検証プロセスの最終結果に影響を与えないため、意味のある'変更とはみなされない。



### `@no-activation`
このタグは、合格した結果が一部の機能部をアクティブにしないことを保証する。その代わり、該当なしとマークされる。

例えば、地理参照ルールである GRF003 は、すべてのIfcFacilityがIfcCoordinateReferenceSystem にリンクされているかどうかを検証する。しかし、IfcFacilityがあるからといって、必ずしもそのファイルが地理参照を含むことを意図しているとは限らない。したがって、地理参照が必要でない場合、このルールは、ソフトウェア認証のスコアカード上で、その機能部分を緑色にマークする"合格"ステータスをトリガーすべきではない。

ルールに@no-activationのタグを付けると、データベースに記録された情報がフィルタリングされ、ルールは合格とマークされない。 

**このタグはエラーの結果には影響しない**。ルールが失敗しても、エラーは発生し、通常どおり記録される。
